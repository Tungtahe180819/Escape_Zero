## Open findings

### QA-001 — Level 03 respawn cooldown is never armed (medium; repaired, browser retest pending)

File: `src/scenes/levels/Level03Scene.ts`, local `respawn` callback.

The callback checks `recovering` and schedules `recovering = false` after 100 ms, but never sets it to true. The update-loop recovery guard is consequently inactive.

Reproduction: extract the actual callback through the TypeScript AST, execute in an isolated sandbox, and call twice before executing delayed callbacks. Observed: two body resets and two timers. Expected: one reset and one timer.

This establishes the reentrancy defect without claiming an observed browser freeze. Multiple respawn sources can execute in the same frame; actual gameplay impact needs a targeted browser test.

Applied with explicit user approval: set `recovering = true` immediately after the early-return guard and before resetting the player. No other gameplay logic changed.

Retest: two immediate calls produce one reset and one timer; the 100 ms callback clears the lock; a subsequent respawn works again. Completed-level and missing-body guards still prevent respawn without arming the lock. All 19 isolated system tests, TypeScript and a fresh production build pass. Actual browser fall/capture/checkpoint restart retest remains pending.
